# ao3-formatter

一个纯前端的小工具：粘贴文字、点按钮调格式、下载一份可以直接粘进 AO3「HTML 模式」编辑器的代码。不需要后端，不需要安装任何东西，部署在 GitHub Pages 上就能用。

在线地址：
https://euclase2333.github.io/ao3-formatter/

## 这是什么、能干什么

AO3 的作品编辑器有个「HTML 模式」，支持一部分 HTML 标签（比如 `<strong>`、`<em>`、`<blockquote>`），但**不支持大多数行内 `style="..."` 属性**。所以想要调字号、行距、段距、首行缩进这些效果，没法直接写 `style`，得用一种叫 **Work Skin（作品皮肤）** 的东西：

1. 正文里只写 `class="xxx"`，不写 `style`。
2. 在 AO3 后台新建一个 Work Skin，把对应的 CSS 规则粘进去。
3. 发布作品时选中这个 Work Skin，AO3 就会按这份 CSS 渲染你的 class。

这个工具做的事情就是：

- 让你在网页上边看效果边调格式；
- 自动生成只用 `class` 不用 `style` 的干净 HTML；
- 顺便把配套的 Work Skin CSS 一起打包进下载的 txt 文件里，你复制粘贴就行，不用自己写 CSS。

## 本地怎么打开

不需要安装任何东西。三个文件（`index.html`、`style.css`、`script.js`）放在同一个文件夹里，双击 `index.html`，用浏览器直接打开就能用。

## 部署到 GitHub Pages

如果你是按照下面聊天里的步骤操作的，仓库根目录已经有 `index.html`。去仓库的 **Settings → Pages**，在 **Source** 里选 `main` 分支、目录选 `/ (root)`，点 **Save**。等一两分钟，页面顶部会出现一个链接，形如：

```
https://你的用户名.github.io/ao3-formatter/
```

打开它就是这个工具。

## 怎么用（使用流程）

1. **粘贴原文**：把你的文字粘贴到最左边的输入框，点「载入到预览区」。文字会按**换行符**自动分段——每一行就是一段，空行会被跳过（不再要求隔一个空行才分段）。
2. **调格式**：
   - 加粗 / 斜体 / 引用 / 字号：在中间预览区里用鼠标选中一段文字，再点右边对应的按钮，预览区会立刻更新。
   - 首行缩进：不选中任何文字，直接点「首行缩进」按钮 = 对全文所有段落统一开关；先选中某一段文字再点 = 只单独开关这一段。
   - 行间距 / 段间距：**不需要选中**，直接拖动滑块或在数字框里输入数值（行距是倍数，比如 1.6；段距单位是 em，比如 1），对全文立即生效。
3. **下载**：调整满意后，点底部「下载 ao3-formatted.txt」，会得到一个 txt 文件；或者点「复制到剪贴板」直接复制。
4. **粘贴到 AO3**：
   - 打开 txt 文件，把最前面那一整段 `<!-- ... -->` 注释里的 CSS（不包括注释符号本身）复制出来。
   - 登录 AO3，进入 **Dashboard → Skins → Create Work Skin**，粘贴这段 CSS，保存皮肤。
   - 回到你要发布/编辑的作品页面，在 **Work Skin** 的下拉框（一般在 "Preface" 或工作设置里的 "Select Work Skin"）选中刚才创建的皮肤。
   - 在正文编辑器切换到 **HTML** 模式，把 txt 文件里注释**之后**的那部分正文 HTML（`<p>...</p>` 那些）粘贴进去。
   - 切回预览查看效果，确认没问题再发布。

## 格式按钮说明

| 按钮 | 作用 | 生成的标签/class | 是否需要 Work Skin |
|---|---|---|---|
| 加粗 | 选中文字加粗 | `<strong>` | 不需要，AO3 原生支持 |
| 斜体 | 选中文字变斜体 | `<em>` | 不需要，AO3 原生支持 |
| 引用 | 选中段落变成引用块 | `<blockquote>` | 不需要，AO3 原生支持 |
| 大字号 / 正常字号 / 小字号 | 调整选中段落文字大小 | `class="fs-large"` / 无 / `class="fs-small"` | 需要 |
| 行间距（数字，1~3 倍） | 调整**全文**行距，不需要选中 | 写进 Work Skin 的 `line-height` 数值 | 需要 |
| 段间距（数字，0~3 em） | 调整**全文**段落上下间距，不需要选中 | 写进 Work Skin 的 `margin-top`/`margin-bottom` 数值 | 需要 |
| 首行缩进开关 | 不选中文字 = 全文段落统一开关；选中某段文字 = 只给这一段首行加/去两字缩进 | `class="indent"` | 需要 |
| 清除选中格式 | 去掉选中文字的加粗/斜体等，只留纯文本 | - | - |
| 撤销上一步 | 调用浏览器自带的撤销（Ctrl+Z / Cmd+Z） | - | - |

「正常字号」按钮是用来把段落字号改回默认状态的，导出时不会生成多余的 class。行间距和段间距不再是按段落挑的档位，而是滑动/输入一个具体数值，直接对全文生效，导出时会把这个数值写进 Work Skin 里的 `#workskin p, #workskin li, #workskin blockquote` 规则。

「载入到预览区」时默认**不会**给段落加首行缩进（避免和粘贴进来的文字自带的手动缩进重复）。首行缩进统一交给「首行缩进」按钮处理：预览区里没有选中任何文字时点击 = 对全文所有段落一起开关；先选中某一段文字再点击 = 只单独开关这一段。

## 导出规则（给感兴趣的人看）

下载/复制时，工具会：

1. 遍历预览区里的所有标签，删掉所有 `style` 属性和不在白名单里的 `class`。
2. 只保留这些标签：`p`、`strong`、`em`、`blockquote`、`br`、`hr`、`ul`、`ol`、`li`；其它标签（比如浏览器自动生成的 `div`、`span`）会被展开，只留里面的文字内容。
3. `class` 白名单：`fs-large`、`fs-small`、`indent`（行距/段距不再走 class，而是直接把当前设置的数值写进 Work Skin CSS，对全文生效）。
4. 在导出文本最前面附上一段说明注释，包含配套的 Work Skin CSS，其中行距/段距的数值就是你在页面上当前调好的那两个数字。

## 常见问题

**Q: 点了格式按钮没反应？**
A: 加粗/斜体/引用/字号，要先在中间预览区里用鼠标选中一段文字，再点按钮，是按"段落"生效的，选中那一段里的任意文字即可，不用整段全选。行距/段距不用选中，直接拖数字。首行缩进比较特殊：不选中直接点 = 对全文生效；想单独调某一段，才需要先选中那一段。

**Q: 下载的 txt 里正文和 CSS 都在一起，会不会把 CSS 也粘到 AO3 正文里？**
A: 不会，但你需要自己动手把两部分分开：注释 `<!-- -->` 里面是 CSS，粘到 Work Skin 里；注释外面的 `<p>...</p>` 部分才是粘到正文 HTML 模式里的内容。

**Q: GitHub Pages 打开是 404？**
A: 确认仓库里根目录直接有 `index.html`（不是放在子文件夹里），并且 Settings → Pages 里 Source 选的是有内容的那个分支（比如 `main`），保存后等 1-2 分钟再刷新。

**Q: 更新了 `style.css` / `script.js` 之后，GitHub Pages 上还是旧样式？**
A: 这是浏览器 + GitHub Pages 的 CDN 缓存共同造成的，不是部署失败：
- GitHub Pages 走的是 Fastly CDN，边缘节点缓存通常在几分钟到十分钟内会更新，但用户自己浏览器缓存的 `style.css`/`script.js` 可能会保留更久（取决于浏览器策略）。
- 因为 `index.html` 里引用的是固定文件名（`style.css`、`script.js`），浏览器一旦缓存过这两个文件，即使内容变了、文件名没变，浏览器也可能继续用本地缓存，不会重新请求。
最简单的解决办法是给引用加一个版本号查询参数（cache busting），每次改动就换一个值，例如：
```html
<link rel="stylesheet" href="style.css?v=2">
...
<script src="script.js?v=2"></script>
```
因为 URL 变了，浏览器会当成新资源重新下载，不会受旧缓存影响。你自己在本地测试时，也可以用浏览器的强制刷新（Windows/Linux: Ctrl+Shift+R，Mac: Cmd+Shift+R）或者无痕窗口打开来跳过缓存确认效果。

本项目的 `index.html` 已经带了 `?v=2` 这样的版本号。以后每次改完 `style.css` 或 `script.js` 想立刻让访客看到新版本，就把 `index.html` 里对应引用的 `?v=数字` 加一，比如改成 `?v=3`。

**Q: 预览区效果和 AO3 上不一样？**
A: 预览区只是"模拟"AO3 的默认阅读样式，不是 100%还原；具体效果以你在 AO3 发布后、应用了 Work Skin 之后的实际页面为准。
